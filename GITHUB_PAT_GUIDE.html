02｜第一次：設定 SSH

在 Mac「終端機」或 Windows「Git Bash」確認：

git --version
python3 --version

若 Mac 沒有 Git，可執行 xcode-select --install。Python 3 需能以 python3 啟動；脚本只使用內建函式庫，不需要安裝 pip 套件。

已有可登入 kuonanhong 的 SSH 金鑰

直接測試：

ssh -T git@github.com

第一次連線時，請依 GitHub 官方 SSH 指紋確認主機。看到 Hi kuonanhong! You've successfully authenticated… 代表成功；GitHub 不提供 shell，所以這個測試回傳結束碼 1 是正常的。

還沒有 SSH 金鑰

  1. 依 官方金鑰設定教學建立 Ed25519 金鑰。若已存在同名金鑰，不要覆蓋。
  2. 將公鑰（檔名以 .pub 結尾）加入 GitHub → Settings → SSH and GPG keys → New SSH key → Authentication Key。私鑰留在自己的電腦。
  3. 把金鑰加入 SSH agent，再執行上面的連線測試。脚本沿用系統 ~/.ssh/config 與 agent；為了隔離 Git filters，它不讀取全域 Git core.sshCommand，自訂金鑰請設定在 SSH config。

提交作者若尚未設定，使用你想顯示在 GitHub 的姓名與 email：

git config --global user.name "你的 GitHub 顯示名稱"
git config --global user.email "你的 GitHub 已驗證或 noreply email"

03｜把脚本放進資料夾，先預覽

將 Upload_FRAME_SSH.sh 放到 FRAME_AI_Studio 內，與 index.html 同一層。開啟終端機，輸入 bash （後面有一個空白），把脚本拖進終端機，再加上 --dry-run 後按 Enter。

bash "/你的路徑/FRAME_AI_Studio/Upload_FRAME_SSH.sh" --dry-run

脚本會自動辨識同一層的專案，也可用 --source 明確指定。這對脚本放在「下載項目」而專案放在其他位置特別方便：

bash "/脚本路徑/Upload_FRAME_SSH.sh" \
  --source "/你的路徑/FRAME_AI_Studio" --dry-run
預覽不推送。它會讀取遠端、在獨立快取建立不可變內容快照，逐檔比較 Git blob hash 與執行權限，列出新增/修改、相同略過數量、排除檔案與網站總大小。只修改時間而內容相同的檔案不會重傳。計畫 last-plan.json 路徑會印在終端機。

省略 --dry-run 也仍是預覽。脚本不會在你的專案執行 git init、git add .、reset 或 clean。

04｜確認清單後，執行上傳

bash "/你的路徑/FRAME_AI_Studio/Upload_FRAME_SSH.sh" --push

有 --source 就沿用同一條完整指令，把 --dry-run 改成 --push。這個旗標表示你要把通過檢查的檔案寫入指定 GitHub 儲存庫。

階段脚本做什麼主站狀態
比對與檢查讀取當下 main；保留既有檔案；檢查秘密、大小、分塊 SHA-256 與檔案/資料夾衝突。不變
分批上傳將新增/變更內容以約 128 MiB 一批推送到 frame-upload/… 暫存分支；分塊優先。main 不變
完整發布全部批次完成且最終樹狀內容吻合，才用一般 fast-forward push 一次更新 main。Pages 可開始建立完整新版

第一次需上傳尚未存在的瀏覽器模型。以後若只改文案或程式，模型雜湊相同就跳過。檔案改過便以新 blob 儲存；Git 是否能進一步壓縮取決於內容。

想先傳完模型，稍後再發布

bash "/你的路徑/FRAME_AI_Studio/Upload_FRAME_SSH.sh" --push --stage-only

# 準備發布時，移除 --stage-only，再執行：
bash "/你的路徑/FRAME_AI_Studio/Upload_FRAME_SSH.sh" --push

中斷時直接重跑相同指令。脚本會驗證遠端暫存樹的每個檔案是否屬於本次計畫，再續傳剩餘內容；已經發布且完全相同則不產生新提交。若 main 在過程中被更新，脚本停止，重跑後再依最新 main 合併本次檔案。若來源在兩次執行之間改變，會建立另一個對應版本的暫存分支。

沒有使用 force push；不刪除遠端既有檔案、不改寫歷史。遠端舊檔案即使本機已刪除仍會保留，這是有意的保留策略。暫存分支在完成後保留，不會自動刪除。

05｜確認 GitHub Pages 發布位置

  1. 開啟 Frame_to_Video → Settings → Pages。
  2. 若用分支發布，Source 選 Deploy from a branch，Branch 選 main，Folder 選 /(root)。
  3. 不要把 frame-upload/… 設成 Pages 來源。若你本來使用自訂 Actions workflow，請確認它只在 main 完整更新後部署；脚本不會新增或修改 .github/ workflow。
  4. 在 Actions 確認 Pages build/deployment 成功，再開 https://kuonanhong.github.io/Frame_to_Video/。

上傳成功代表 Git 已收到檔案，不代表 Pages 已完成部署。若仍看到舊畫面，先確認部署提交與脚本印出的 SHA 相同，再按住 Shift 點重新整理，或使用無痕視窗檢查。不要為了本網站刪除其他網站的 service worker。新入口也可直接開 /Frame_to_Video/FRAME_AI_Studio/。

06｜模型分塊與容量：哪些上傳，哪些留在本機？

項目策略
story/models/smollm2/onnx/model_quantized.onnx.part000…003沿用 4 塊與原 .parts.json；每塊 ≤40 MiB。上傳前驗證每塊與合併後 SHA-256。
story/models/piper/*.onnx.part000…001每個聲音沿用 2 塊；與原載入器順序相同，不重新命名。
edge/model/coco-ssd-lite/既有 TFJS shards 可正常上傳；未變更的分片跳過。
原生大型影像/影片模型native_cpu/models/、backend/models/、weights/、checkpoints/ 與 .safetensors/.ckpt/.pt/.pth/.gguf/.bin 等排除。從 Hugging Face 下載到本機，保留模型 ID、revision、授權與取得方式。
秘密、快取、封存與依賴排除 .env*、SSH 私鑰、credentials、node_modules/、.venv-native/、.runtime/、快取、輸出、ZIP；story/vendor/source/ 內對應授權原始碼封存保留。UTF-8 文字內容掃描常見 GitHub/HF Token 與私鑰標記；二進位權重以 manifest SHA-256 驗證。

這延續「拆成小塊，再依 manifest 重組」的方法。拆檔解決單檔限制，不會減少模型總量，也不會把 GPU 模型變成瀏覽器 CPU 模型。大型原生權重不能靠 Git LFS 指標在 Pages 執行；這份部署不使用 Git LFS。

脚本的保守門檻

  • 每個新上傳檔案嚴格小於 100 MiB。
  • 瀏覽器 .partNNN 分塊不得大於 40 MiB。
  • 保留遠端檔案後的全部 Git tree 總量小於 1,000,000,000 bytes。
  • 每批預設約 128 MiB；可用 --batch-mib 64 降低。

GitHub 官方限制

  • 瀏覽器上傳單檔 25 MiB；一般 Git 單檔 100 MiB 限制。
  • 單次 Git push 限制 2 GiB。
  • 已發布 Pages 網站不可超過 1 GB。
  • Pages 軟性每月頻寬 100 GB；大型模型會消耗訪客下載頻寬。

總量檢查是針對儲存庫根目錄發布的保守估算，包含所有保留檔案；不等同於 Git 歷史大小或伺服器實際壓縮大小。模型更新會累積 Git 歷史，經常更換大型權重時應改用模型託管服務。

07｜遇到問題

訊息／情況下一步
Permission denied (publickey)先讓 ssh -T git@github.com 成功且顯示 kuonanhong。確認 key 已加入 agent、公鑰已加入正確帳號。
分支保護／repository rules 拒絕脚本不繞過保護、不強推。暫存內容仍保留；依儲存庫既有規則由管理者合併或調整授權。
中途斷線重跑相同指令。若主機已收到但回覆遺失，脚本會重新檢查遠端 SHA；無法確認就停止。
快取正在使用先確認沒有上傳程序。若先前被強制關閉，依訊息檢查 running.lock/pid.txt，只刪除該鎖資料夾；不要刪除來源。
分塊缺少／SHA-256 不符從完整交付包重新解壓原始模型檔；不要修改 manifest 來略過檢查。
舊頁面還存在確認 Pages 是 main/root、Actions 已完成、根轉址存在；再用無痕視窗測試。
在 file:// 開啟時 AI 停用本機使用 Start_Mac.command 或對應啟動器開 localhost；網路版使用 HTTPS Pages。
