1 · 為什麼出錯？

v5 的 --download 先安裝模型執行環境；LivePortrait 與 modern 設定使用 torch 2.6。PyTorch 官方 macOS x86_64 套件支援止於 2.2.x，因此 v5 在開始下載前就中止。模型權重本身可以跨平台下載，不應被這個檢查一起阻擋。

v5.1 偵測 Intel macOS 時，您原本的四條 --download 指令會自動切換為純權重下載。使用獨立的 _downloader/venv 安裝 Hugging Face Hub 0.36.0，不會為下載安裝 Torch、CUDA 或模型推論套件。

2 · 套用修補包

  1. 解壓縮 FRAME_Intel_Download_Fix_v5_1.zip。
  2. 回到您原先顯示 FRAME_AI_Studio % 的終端機；先關閉正在執行的本機模型服務。
  3. 執行以下命令（修補包若不在 Downloads，請替換其路徑）。
python3.11 "$HOME/Downloads/FRAME_Intel_Download_Fix_v5_1/apply_fix.py" .

腳本會檢查專案根目錄、驗證修補檔雜湊、備份被修改的程式、再覆寫檔案。備份位置會印在終端機。不要直接以 Finder 替換整個 advanced_service 資料夾，以免移走原有檔案。

若要還原，使用套用時印出的備份路徑：

python3.11 "$HOME/Downloads/FRAME_Intel_Download_Fix_v5_1/apply_fix.py" --restore "/完整備份路徑/v51_時間_識別碼"

還原工具遇到您在套用後又修改的檔案時會停止，避免覆蓋新內容。

此次不需要重新下載整份 FRAME 網頁套件，也不用更動 Conda base 環境。若已自行修改同名程式，請先比較自動備份。

3 · 一次下載四個模型

仍在 FRAME_AI_Studio 根目錄執行。先查容量：

bash advanced_service/Download_Four_Models.sh --plan

正式下載（依序執行，一個完成後才下載下一個）：

bash advanced_service/Download_Four_Models.sh --download

或逐一下載：

python3.11 advanced_service/install.py liveportrait --weights-only
python3.11 advanced_service/install.py flux-klein --weights-only
python3.11 advanced_service/install.py ltx-video --weights-only
python3.11 advanced_service/install.py cogvideox --weights-only

Intel Mac 上也可沿用原本的 --download 寫法；上列 --weights-only 將意圖寫得更清楚，在 Linux 或 Windows 同樣只下載權重。不要把成功文字 WEIGHTS READY 當成模型生成通過。

合計 63.668 GB（59.30 GiB），不含下載套件、執行環境與暫存。建議準備至少 80 GB 可用空間；這是儲存空間，不是 RAM。資料來自上述固定版本官方 metadata；之後版本可能不同，以 --plan 為準。

預設路徑為 advanced_service/.runtime/模型ID/models/。如需外接 SSD，下載前在同一終端機設定：

export FRAME_EXPERT_HOME="/Volumes/你的SSD名稱/FRAME_models"
bash advanced_service/Download_Four_Models.sh --download

更改路徑不會自動搬移舊模型；設定新路徑後會把新位置視為目的地。之後啟動服務與驗證也必須設定同一個 FRAME_EXPERT_HOME。不要將這些大型本機權重提交到 GitHub Pages。

5 · 中斷、續傳與驗證

若網路中斷或按 Ctrl+C，保留模型資料夾及其中的 .cache/huggingface，再執行相同指令。計畫檔 download-plan.json 會保存固定 commit；重試不會自動換成新版模型。

bash advanced_service/Download_Four_Models.sh --verify
# 或只驗證一個模型
python3.11 advanced_service/install.py liveportrait --verify

--verify 完全離線比對檔案大小與 SHA-256，讀取大型模型需要時間。僅 --plan 不會產生已下載狀態；完成下載才寫入 weights-manifest.json。

明確要採用上游新版本時才使用 --refresh-plan。新版本可能與原執行環境不相容；模型路徑與原安裝共用，更新前應自行備份正在使用的權重。

python3.11 advanced_service/install.py flux-klein --plan --refresh-plan

檔案毀損會被 SHA-256 驗證擋下，不會產生新的成功收據。重新下載毀損檔案前，須移開該檔及其對應的下載 metadata；不要刪除整個模型庫。網路 SSL、403/429 或連線逾時與原本的 Torch 錯誤不同，請保留完整錯誤訊息排查。

6 · 能下載與能生成的差別

模型本次處理Intel Mac 原生生成
LivePortrait人像模式權重；不另外下載動物模型與 Git 原始碼。官方 CPU 分支仍屬實驗性；Intel 未完成實測。此補丁不加入舊版 Torch 試驗環境。
FLUX.2 kleinDiffusers 格式，並補回漏掉的 tokenizer/chat_template.jinja。v5 的 Torch 2.6 pipeline 不能原樣在官方 Intel wheel 上執行。stable-diffusion.cpp 是另一條候選路線，需要不同模型格式與另外整合。
LTX / CogVideoX選定的 0.9.5 與 5B I2V 權重完整清單。此版沒有經驗證的 Intel Mac 原生生成環境。可另建支援新 Torch 的 Linux 環境，但不能保證 CPU 速度、RAM 足夠或提示詞效果。

沒有以刪除平台檢查、把版本號改低或假造生成輸出來宣稱相容。若目前目標是四個模型都在您的 i9 Mac 實際生成，還需要逐一移植與實機驗證；此下載修補包不代表該工作已完成。
