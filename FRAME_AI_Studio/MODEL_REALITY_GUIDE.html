把模型放在自己的電腦

10 個模型與方法的實際輸入、CPU 適用範圍、套件介面與研究來源。以 Intel Mac 64 GB 作為容量規劃情境，手機與平板可使用基本瀏覽器剪輯。

資料查閱日期：2026-10-10 · 技術來源以作者模型卡、官方程式庫、官方文件與論文為主。

模型文件已核對；本版的實測狀態請以 VALIDATION_V5.html 為準。
這份指南不代表模型已安裝，也不代表 Intel Mac 或手機已完成生成。健康檢查通過只證明服務可連線；真正的模型測試需載入正確權重並產生可檢查的輸出。

先選對執行位置

GitHub Pages 提供網頁檔案。本機 Python 或 llama.cpp 服務載入模型、使用 CPU 計算，再把結果交回瀏覽器。iPhone、iPad 與 Android 可使用瀏覽器剪輯器；本版模型服務僅允許同一電腦的本機瀏覽器，未提供手機遠端連入電腦的生成服務。手機上的 127.0.0.1 是手機本身。

離線使用需先下載套件與模型。使用本機模型資料夾、local_files_only=True，並記錄下載 revision。模型檔案不應放進 GitHub Pages 專案。大型影片任務一次只載入一個模型；完成後卸載可讓 64 GB 留給下一個任務。

Intel Mac 的版本邊界

官方 PyTorch macOS x86 wheel 到 2.2.x 為止，可取得 2.2.2。不要把 Apple Silicon 的 MPS 教學視為 Intel Mac 支援。較舊圖像模型可以在固定的 legacy 環境嘗試；FLUX.2 與新影片 pipeline 適合分離為較新的 Linux x86 CPU 環境。Linux 虛擬機仍使用同一台 Mac 的 CPU 與 RAM，不會因此變快。

Diffusers 0.37.0 已包含 Flux2 Klein；0.37.1 的 FLUX.2 程式碼直接使用 torch.nn.RMSNorm，官方 Intel macOS 的 torch 2.2.2 缺少這個類別，因此該標準 pipeline 無法原樣運行。Diffusers 0.39 以後也將 PyTorch 最低版本提高至 2.6。舊版套件的寬鬆 metadata 不保證每個新 pipeline 都能在 torch 2.2.2 執行。請把「依賴可解析」「可 import」「模型載入成功」「生成成功」分開記錄。

PyTorch 2.2：macOS x64 支援公告 ↗ 官方 PyTorch CPU wheel 索引 ↗ Diffusers 0.37.0 release：新增 Flux2 Klein ↗ Diffusers 0.39.0 release ↗ FLUX.2 0.37.1 原始碼：直接使用 torch.nn.RMSNorm ↗

CPU offload 不是 CPU-only

enable_model_cpu_offload() 與 enable_sequential_cpu_offload() 將權重暫放 CPU、按需送回加速器。真正 CPU 路徑要指定 to("cpu") 與 CPU generator，並使用 CPU 可執行的 dtype。Intel 舊 CPU 通常以 float32 作為保守起點；float16／bfloat16 是否有效及較快，必須依硬體與算子檢查。

stabilityai/stable-diffusion-2-base

FLUX.2 klein 4B

下載識別碼
black-forest-labs/FLUX.2-klein-4B
輸入 → 輸出
文字；可另加 PIL 參考圖片 → 圖片
執行介面
Flux2KleinPipeline
Intel Mac / CPU
Diffusers 0.37.0 起有 Klein；Qwen3 text encoder 需 Transformers 4.51+。官方 Intel macOS torch2.2.2 缺少此 pipeline 直接使用的 torch.nn.RMSNorm，無法原樣執行；需較新 PyTorch 的 Linux x86 CPU 環境。

  • 官方低於一秒與約 13 GB VRAM 資訊是 GPU 情境，不能用作 Intel CPU 效能承諾。
  • 4-step distilled checkpoint 使用 guidance_scale=1；不替換成 FLUX.1 或假裝現有 SD adapter 即可。
  • 本次未找到可可靠配對此 checkpoint 的正式 arXiv 論文；引用官方模型卡與程式庫。
